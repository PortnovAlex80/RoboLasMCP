# Демо RoboLas MCP — «покажи, на что способен»

Готовый текст для демонстрации ИИ-агенту, подключённому к Robur через MCP.
Вставляешь промпт в клиента (Claude / Hermes / Cursor / любой HTTP MCP) — агент
сам прогоняет сценарий по цепочке тулзов `las_*` и комментирует каждый шаг.

## Что нужно перед демо (2 минуты)

1. Robur (Rail/Road) **16.0.62.12+**, установленный плагин **robur-mcp**
   (пакет Топоматика), установленный **RoboLas + MCP-адаптер** (наш пакет).
2. Открытый в Robur **тестовый проект с трассой и LAS-облаком** на ЦММ трассы.
   ⚠️ **Работайте на копии проекта**: демо строит ЦММ и пересоздаёт сечения —
   это меняет проект (на это и демонстрация).
3. MCP-сервер запущен (при открытии проекта стартует сам; иначе кнопка
   «Запуск MCP» на вкладке RoboLas). Конфиг клиента:

```json
{ "mcpServers": { "robur": { "type": "http", "url": "http://127.0.0.1:8000/mcp/" } } }
```

## ПРОМПТ 1 — «Полное демо» (10–15 минут)

Скопируйте ЦЕЛИКОМ и отправьте агенту:

```text
Ты подключён к Topomatic Robur через MCP-плагин RoboLas (тулзы las_*).
Проведи демонстрацию возможностей: выполняй шаги по порядку и после КАЖДОГО
тула объясняй коротко и по-русски, что ты узнал/сделал и почему следующий
шаг именно такой. Оформляй этапы заголовками, сравнения — таблицами.

Правила безопасности:
- Если precondition шага не выполнен (нет трассы, нет LAS, нет сечений) —
  не выдумывай параметры: объясни, что не так, и предложи, как исправить.
- Если трасс несколько — покажи список и попроси меня выбрать.
- Пишущие операции выполняй только через шаблон: las_preflight → вызов тула
  с request_id (придумай уникальный) и expected_context из preflight.
- Если тул вернёт cancelled=true (я нажал «Отмена» в Robur) — сообщи и
  спроси, повторять ли.

Этап 1 — Разведка (только чтение):
1) las_get_capabilities — расскажи одним абзацем, что умеет RoboLas MCP.
2) las_get_context — состояние: проект, активная трасса, сечения, ЦММ,
   LAS-облака (файлы и число точек). Запомни surface_points — это база
   для сравнения «до/после».
3) При необходимости las_list_alignments и las_set_active_alignment
   (с моего подтверждения, если трасс несколько).

Этап 2 — Глубокое чтение облака:
4) las_list_sections (max_sections=10) — покажи диапазон пикетов.
5) las_get_section_points: station = средний пикет из списка, thickness=1.0.
   Объясни гистограммы плотности и пустоты по осям; сделай вывод, годится ли
   толщина 1.0 м для построения ЦММ или посоветуй другую.
6) las_render_section: тот же пикет, thickness=1.0, color_by="z". Прочитай
   image.path как ИЗОБРАЖЕНИЕ и опиши словами, что видно на поперечнике
   (рельеф, рельсовые нити, бровки, шум). Это PNG-кадр сечения с калибровкой
   пиксель↔метр — покажи, что ты «видишь» облако глазами.

Этап 3 — Подготовка записи (покажи контракт безопасности):
7) las_preflight для las_generate_sections с аргументами {"step": 1.0}.
   Объясни, что preflight валидирует схему и снимает «отпечаток» проекта.
8) Выполни las_generate_sections с теми же аргументами + request_id +
   expected_context из preflight. Сечения пересоздаются — предупреждай.
   (В Robur появится прогресс-бар — это нормально.)

Этап 4 — Главный сценарий:
9) las_preflight для las_build_terrain {"thickness": 0.25, "step": 1.0},
   затем выполни его по тому же шаблону. Прогресс идёт в Robur; дождись.
10) las_get_context — таблица «до/после»: surface_points, сечения. Вывод:
   на сколько выросла ЦММ.

Этап 5 — Журнал операций:
11) las_list_operations — покажи историю записей этой сессии; возьми
    последний id и вызови las_get_operation — объясни, что агент может
    проверить результат после таймаута, не повторяя запись вслепую
    (replay защищён request_id).

Этап 6 — Экспорт без риска для проекта:
12) las_preflight для las_reduce_cloud {"percent": 25,
    "output_path": "%TEMP%\\robolas_demo_reduced.las", "ground_filter": false},
    затем выполни. Отчитайся: сколько точек было/осталось, куда записан файл.
    Напомни: облако в проекте не изменилось, файл можно импортировать в Robur.

Финал:
13) Сводка демо: список вызванных тулзов цепочкой, что менялось в проекте,
    что нет; 3 идеи, что ещё можно попросить (из las_get_workflow_guide).
```

## ПРОМПТ 2 — «Экспресс» (3 минуты, только чтение, проект не меняется)

```text
Ты подключён к Robur через MCP-плагин RoboLas (тулзы las_*). Короткое демо
без изменения проекта:
1) las_get_capabilities — одним абзацем: что умеет.
2) las_get_context — состояние проекта/трассы/ЦММ/облака.
3) las_list_sections (max_sections=5), затем las_get_section_points на
   среднем пикете (thickness=1.0) — покажи плотность точек и пустоты,
   объясни, что это значит для качества ЦММ.
4) Итог: 5 пунктов «что я могу сделать дальше» на основе next_steps из
   ответов тулзов.
```

## ПРОМПТ 3 — «Навигатор сценариев» (показ подсказок next_steps)

```text
Ты подключён к Robur через MCP-плагин RoboLas. НЕ выполняй пишущие тулы.
1) Вызови las_get_workflow_guide и перескажи сценарии «Прореживание» и
   «Удаление точек по полигонам» как пошаговый план с аргументами.
2) las_get_context — скажи, какой сценарий сейчас выполним, чего не хватает.
3) Ответь на мой вопрос: «как убрать шум под мостом, сохранив проект?» —
   пользуясь только фактами из тулов.
```

## Контрольные точки (как понять, что демо удалось)

| Шаг | Что вы должны увидеть |
|---|---|
| Этап 1 | Агент называет проект/трассу и число точек облака из вашего проекта |
| Этап 2 | Гистограммы плотности; осмысленный совет по толщине слайса |
| Этап 3–4 | В Robur появлялись прогресс-бары; сечения пересоздались; surface_points вырос в таблице «до/после» |
| Этап 5 | Список операций с request_id последней записи |
| Этап 6 | Файл `%TEMP%\robolas_demo_reduced.las` существует; «удалено/оставлено» точек сходится |

## Если что-то не так

- `тулов las_* не видно` → сборка Robur < 16.0.62.12, robur-mcp не установлен,
  сервер не запущен: проверьте `http://127.0.0.1:8000/health`, кнопку
  «Запуск MCP», Topomatic.ToolBridge.dll в каталоге Robur.
- `Project or settings changed since preflight` → между preflight и записью
  менялись настройки/проект — агент получит новый expected_context через
  повторный las_preflight (попросите его повторить).
- `уже выполняется` → предыдущая операция ещё идёт; повторите позже.
- Лог установки/бэкапы: `C:\ProgramData\RoboLas\`.
## Демо 4 (NEW, 04.10): визуальная чистка сечений «глазами» агента

Цепочка `las_render_section` → `las_preview_section_polygon` → `las_delete_section_points`
(docs/MCP_SECTION_VISUAL.md). Запускать при открытом проекте с трассой и облаком.

1. Осмотр: `las_render_section {station: 250, thickness: 0.3}` — открой PNG из
   `result.image.path` как изображение; подбери thickness (тоньше/толще).
2. Полигон по объекту на картинке (координаты — offset, Z из подписей осей кадра):
   `las_preview_section_polygon {station: 250, thickness: 0.3,
   polygons: [[[-2,101],[-1,101],[-1,103],[-2,103]]]}` — проверь по PNG с
   нарисованным полигоном, что он накрыл объект; счётчик `matched_points` = сколько
   точек уйдёт; толщина сечения одна — она же и глубина вырезаемого слоя,
   меняй thickness/вершины, пока не попадёшь.
3. Удаление (можно накопить несколько пикетов за один вызов):
   `las_delete_section_points {output_path: "D:\exports\cleaned.las",
   sections: [{station: 250, thickness: 0.3, polygons: [[...]]}]}`.
4. Цикл по следующему пикету: шаг 1. Результат — новый LAS, импорт в Robur вручную.
