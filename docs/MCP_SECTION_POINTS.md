# MCP: точки сечения и плотность

`las_get_section_points` — только чтение через MCP. Пользователь сообщает агенту пикет и цель подбора толщины; агент читает срезы облака, уже загруженного в Robur. Меню, постоянные сечения, ЦММ и настройки не изменяются. Внешние LAS не требуются.

Пример аргументов для `tools/call`:

```json
{
  "name": "las_get_section_points",
  "arguments": {
    "station": 1234.0,
    "thickness": 0.3,
    "bin_size": 0.5,
    "slice_bin_size": 0.05,
    "point_offset": 0,
    "max_points": 2000
  }
}
```

`station` — метры от начала активной трассы: ПК 12+34 = 1234. `thickness` — полная толщина: строго между −0.15 и +0.15 м для примера. Поперечные границы берутся из DtmSizeLeft/Right трассы. Существующее сечение на этом пикете не требуется.

`result.Points` содержит исходные XYZ, `Offset` (поперечное смещение: слева отрицательное), `Elevation` (Z проекта), `SliceDistance` (расстояние по нормали коллектора до плоскости сечения). Последнее не является разностью пикетов на кривой трассе.

| Поле result | Значение |
|---|---|
| TotalPoints | Все исходные записи, принятые коллектором |
| Points / ReturnedPoints | Страница точек без фильтра земли и прореживания |
| NextPointOffset | Индекс следующей страницы; null, если больше точек нет |
| OffsetDensity | Статистика поперечного смещения; область от −DtmSizeLeft до правого края |
| ElevationDensity | Статистика высоты; область интервалов, покрывающих наблюдаемые Z |
| SliceDistanceDensity | Статистика расстояния до плоскости; область ±thickness/2 |

Каждая статистика содержит `PointCount`, `Minimum`, `Maximum`, `PointsPerMeter` (N / наблюдаемый размах), `MeanAdjacentSpacing` (размах / (N−1), включая повторные координаты), `DomainPointsPerMeter` (N / ширину области гистограммы), `BinSize`, `DomainFrom/To`, `Bins` (From, To, Count, PointsPerMeter), `EmptyBins`, `OccupiedBinFraction`, `LongestEmptyRun`, `LongestEmptyRunMeters`.

Интервалы привязаны к кратным шагу координатам; крайние интервалы обрезаются границами области. Плотность интервала рассчитывается по его фактической ширине. Верхний поперечный край входит в последний интервал. Плотности одномерные, в точках на метр. При нулевом наблюдаемом размахе PointsPerMeter = null; одна точка не имеет MeanAdjacentSpacing. Пустой срез успешно возвращает нулевые интервалы по поперечной и продольной осям; наблюдаемой области высоты у него нет.

По умолчанию `bin_size=1` м, `slice_bin_size=thickness/10`, `max_points=2000`. Размер страницы ограничен 10000, количество интервалов — 10000 на ось. Статистика всегда по полному срезу. Для получения всего набора нужно запрашивать следующие страницы при неизменном источнике. Каждая страница повторно читает облако; долговременный снимок не создаётся. Повторные записи разных провайдеров сохраняются.

Агент сравнивает несколько толщин при одинаковых шагах гистограмм: заполненность поперечных интервалов, максимальные пустоты, общее число точек и распределение внутри толщины. Толщину выбирает по целям задачи; инструмент не объявляет автоматический универсальный оптимум. Например: «На ПК 12+34 сравни толщины 0.1, 0.3 и 0.5 м, покажи плотность через каждые 0.5 м поперёк и выбери минимальную толщину без пустых интервалов в рабочей полосе».

Ошибки используют общий контракт: `input_schema`, `correct_request`, `next_steps`. При превышении лимита точек частичный результат не выдаётся; уменьшить толщину. Если интервалов слишком много — увеличить bin_size или slice_bin_size. В ответе есть подсказки получения следующей страницы и сравнения другой толщины.

Сборка: основной плагин .NET 3.5, MCP-адаптер .NET 4.8. Проверены новая DLL SDK 16.0.64.2, официальный Topomatic.ToolBridge и JSON 13 из официального TPM; проверка в открытом проекте выполнена: трасса Rail, пикет 250 м, 310 точек при толщине 0.1 м и 926 при 0.3 м. Суммы гистограмм по трём осям совпадают с TotalPoints; страницы и recovery envelope проверены, проект и настройки не изменены.
